# FM Atlas 27 — R7.2.0 Research Notes

Research reviewed for the 13 November 2026 R7.2.0 source pass. This records the useful public technical evidence and the boundaries applied in Atlas. Public project source is treated as untrusted input and its licence is not a blanket permission to copy implementation.

## 1. Live process editing and build profiles

**FMLibreEditor** — https://github.com/tozmoz/FMLibreEditor

- Its README describes a free, open-source FM27 live editor for Windows Game Pass/Microsoft Store and Steam, with macOS Steam support.
- Its development notes describe native `game_plugin.dll` process access, `ReadProcessMemory` / `WriteProcessMemory`, pre-write player identity and value checks, save-load generation tracking, read-back and read-only fallback when the current build or field checks fail.
- Its checked Windows profile files include Game Pass `0.9.2435.0` and Steam build `26385295` (FM27 27.0.1); separate RVAs are used for the two store builds. The profile comments describe a successful test/probe on a specified save and 10 health checks.
- Earlier Windows profiles include Game Pass `0.9.2409.0`, Steam build `26340721`, and launch-preview profiles. Preview profiles without a save-load generation object are not write-enabled in Atlas.
- The object layout file explicitly distinguishes field evidence: some FM27 offsets were carried forward from FM26, while only documented witnessed fields have stronger verification. A module fingerprint match must not be treated as proof that every offset is correct.

**FM editor memory layout research** — https://github.com/barak14/fm-editor

- The FM27 notes describe the `game_plugin.dll` module, player/staff/club arrays and object field offsets.
- The notes explicitly state that the FM27 layout initially copied the FM26 schema and only the fields listed as verified have been checked against FM27. Remaining offsets are inherited leads.
- This project is GPL-3.0-or-later. Atlas uses public memory-layout observations as research and has an independently authored process reader/writer. It does not include the upstream implementation.

### Atlas implementation boundary

Atlas's `Fm27BuildProfiles` contains independent profile records for the listed Windows Steam and Game Pass builds. The current writer is restricted to CA, PA and 47 visible standard player attributes. Five hidden attributes are excluded from live writing because the current field evidence is not independently witnessed in Atlas. Personality, position ratings, staff, clubs, contracts, transfers and loan/structural writes remain blocked. The user must compare baseline values with the game/another editor and perform Apply/Undo on a copied offline save before relying on the writer.

## 2. Statistical fields and player view exports

**FM View Exporter** — https://github.com/ElectroHugin/FM-View-Exporter

- Its FM27 column catalogue documents the in-game player-table Insert Column options and matching CSV headers.
- The inspected catalogue has hundreds of entries spanning core identity, player attributes, goalkeeper attributes, person details, happiness, attacking, passing, defending, physical/general and career statistics.
- Some UI-only icon columns may export blank. The project's notes also warn that Football Manager populates only part of a large selected view and that duplicate headings can occur; Atlas therefore suffixes duplicate imported header names instead of overwriting them.
- Atlas imports CSVs independently, retains their original raw columns and uses numeric values where parsing is safe. Nonnumeric text and symbolic icons remain available in the raw imported row but are not fabricated into numbers.

## 3. Save-file reader

**fmsave** — https://github.com/rhiever/fmsave

- MIT-licensed, read-only reader for FM26/FM27 saves. It can emit structured tables and a validation/coverage report.
- The inspected README describes all 52 player attributes, eight personality attributes, CA/PA, contracts, suspensions, staff/clubs, player season statistics, season history, player match stats, fixtures, league tables, competition rules, injuries, training/mentoring and more.
- It supports FM27 build `27.0.0+2486695` through registered layouts; other FM27 builds can be opened only where the relevant section schema matches and are marked unverified otherwise. A registered build does not imply every field meaning is independently confirmed.
- The reader states that unprovided values remain `None`, that unique IDs and save-local UIDs have distinct joining semantics, and that money remains in the stored unit rather than being automatically converted to the user's display currency.

### Atlas implementation boundary

The save import retains supported tables as raw JSON and indexes every finite numeric field found in the imported player season/match/history rows. The UI labels source value units, keeps missing values absent and does not assume fmsave supports every user's exact FM27 patch. Current per-90 calculations require a recognised minutes denominator and explicit sample floor; outputs still need comparison with FM27 Data Hub for the selected data source.

## 4. Value & Upside Finder formula

Current implementation is a relative screening model, not a prediction of Football Manager's hidden transfer valuation.

1. Build a comparison population from all latest imported save players where CA, PA and positive transfer value are present; apply screening filters only after percentiles are calculated.
2. Calculate tied-rank percentiles across that candidate set for CA, PA and transfer value. Tied values receive an average rank, not an arbitrary UID order.
3. Calculate ability percentile as `0.65 × CA percentile + 0.35 × PA percentile`.
4. Calculate `Value Index = clamp(50 + ability percentile − transfer-value percentile, 0, 100)`.
5. Apply optional max age, max market value in source units, min CA, minimum PA−CA gap and position substring filters.

Interpretation: a higher score means the player's CA/PA ranking sits above his market-value ranking inside the current imported pool. It is not a fair-market price, transfer recommendation, expected ROI or SI valuation. The market value's currency/unit is not converted; users should compare only values from the same save/currency context. A later recruitment-grade model still needs competition/position/age cohort normalisation, contract/wage costs, availability, scouting uncertainty and independent calibration.
