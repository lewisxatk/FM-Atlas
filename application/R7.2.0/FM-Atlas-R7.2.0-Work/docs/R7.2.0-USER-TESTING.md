# FM Atlas 27 — R7.2.0 User Test Plan

## Before testing

- Keep the previous FM Atlas R7.1.0 folder/ZIP untouched.
- Extract R7.2.0 into a new folder.
- Back up `%LOCALAPPDATA%\FmAtlas` before first launch. R7.2 uses schema additions and should preserve existing tables, but test migration against a copy if the existing database contains valuable work.
- Create a NEW COPY of an FM27 offline single-player career. Never test writes against an online/shared career or your only save.
- Record the exact FM27 store (Game Pass or Steam), Windows app version, and FM module profile shown by Tester & Logs.

## Build

1. Install the .NET 8 SDK x64 for Windows.
2. Run `Build-FM-Atlas-27.bat`.
3. If successful, confirm `BUILD SUCCEEDED` in the window and in `build-logs\latest-build.log`.
4. If unsuccessful, send `build-logs\latest-build.log` without editing it.

## Data and search

1. Open Tester & Logs and run all checks.
2. Use the FMSave Bridge to export a copied FM27 save as an Atlas JSON snapshot.
3. Import the JSON snapshot. Review warning, unknown-build and coverage information.
4. Check counts for player, staff, club, player-season stats, player-match stats and player-history tables.
5. Open a sample player's profile. Compare CA, PA, attributes and several statistics against the FM UI. Record field name, player UID, game build, FM UI value and Atlas value.
6. In Attribute Search, test one multi-condition query with 5+ conditions, including GK/outfield fields as appropriate. Missing ratings must not be treated as zero.
7. In Stats Search, test goals, xG/90, passes, tackles, goalkeeper saves, cards and minutes fields only where they were actually imported. Try at least 3 simultaneous conditions and a minimum-minute floor.
8. Export a narrow FM View Exporter CSV and import it. Verify player UID mapping and ensure duplicate column names do not overwrite one another.
9. Open player/club profiles and verify installed face/logo paths using the user's actual graphics folder.

## Live editor — only after data checks pass

1. Load the copied career in the target FM27 process and wait until it is fully loaded.
2. In Atlas, use Load Game. Confirm Tester & Logs shows the expected exact profile, including storefront and build ID.
3. Confirm the selected live player UID and name match the FM screen. Compare CA/PA in an independent tool and the FM UI.
4. Enable Editor for this Atlas session. It defaults OFF after restart.
5. Preview a small CA/PA change on a disposable player and verify the displayed original values before pressing Apply.
6. Apply the edit. Confirm the writer reports read-back success. Press Continue in FM and check the result.
7. Test Undo while the same save remains loaded and the edited values have not changed again.
8. Reload the career or switch to another save and confirm Atlas refuses any stale Apply/Undo plan.
9. Do not test hidden attributes, personality, position, staff, club, contracts, transfers or loans; these are not enabled in the current live writer.

## Send back

- `build-logs\latest-build.log`
- Tester & Logs redacted support ZIP
- A screenshot of the Atlas home/dashboard and the page that failed
- Exact store + FM build and the exact test steps
- If reporting a field mismatch: player UID, field, FM screen value and Atlas value (no full save file required)
