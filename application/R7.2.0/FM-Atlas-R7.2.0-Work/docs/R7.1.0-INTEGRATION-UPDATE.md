# FM Atlas 27 — R7.1.0 Integration Update

## Added in this source update

### Analytics
- Numeric source metric discovery remains driven by the imported save snapshot.
- Added derived season per-90 options for metric keys that can be paired with a minutes field.
- Per-90 calculations use season stats/history only, use the first recognised minutes key (`minutes_played`, `playing_time_minutes`, `minutes`, `mins_played`, `total_minutes`, `minutes_on_pitch`), and enforce a configurable minutes floor (450 by default).
- Per-90 metric discovery is restricted to the season stats/history sidecar tables, excluding minute/appearance/rating/percentage fields from derived options.
- Added CSV export for the currently displayed Analytics results.
- The UI labels the result as derived and does not claim a metric exists if the reader did not expose it.

### Role Fit Lab
- Added an In Possession / Out of Possession role-fit workspace with 23 transparent player-role profiles.
- Scores are weighted averages of imported player attributes on the 1–20 scale.
- Missing attributes are omitted from the score and the UI reports coverage and available attribute count.
- Scores are original Atlas coaching estimates; they are not SI's role formula, positional familiarity ratings, or in-game stars. They should be tuned against actual players and tested before use for recruitment decisions.
- A CSV export is available for ranked results.

### Editor safety
- The local Atlas editor is OFF by default on every application launch and must be enabled for the current session.
- Mass Edit now supports Set, Add, and percentage Scale operations.
- Add and Scale skip players without an existing value; all changes are individually audited.
- Undo now checks that the current value still matches the value recorded by the selected history row. It refuses stale undo operations that could overwrite a later edit.
- CA and PA now save in one SQLite transaction so the local pair does not partially commit.
- None of these controls writes to the running FM process or edits the career save.

### Tester & Logs
- Added a Tester & Logs workspace with local database, log storage, Python/fmsave, FM process, snapshot and safety checks.
- Added redacted diagnostics copy, support ZIP export and recent-log copy.
- Support ZIP contains the report, recent application log and a readme. It intentionally excludes the career save and the SQLite database.
- Personal details (player names, save filename and exact local database path) are excluded by default. An explicit checkbox enables them for users who need a more detailed report.
- Added rolling application logs under `%LOCALAPPDATA%\FmAtlas\logs` and application-wide unhandled exception logging.

### Build and hand-off
- `Build-FM-Atlas-27.bat` now starts the logged build workflow. `Publish-FM-Atlas-27.bat` also logs the self-contained publish process and provides a clipboard-copy prompt.
- `Build-FM-Atlas-27-Logged.bat` records restore and Release build output under `build-logs`, also keeps `latest-build.log`, displays the complete log and offers one-key clipboard copy.
- `Open-FM-Atlas-Logs.bat` opens the build-log folder. Runtime logs are saved separately under `%LOCALAPPDATA%\FmAtlas\logs`.

## What still needs a real Windows/FM test

- WPF compilation and application startup on Windows 10/11 with .NET 8.
- Import of an actual FM27 Game Pass save copy and validation of the parser's returned fields and metrics.
- Verification of the derived per-90 minutes-key mapping and sample thresholds against FM27 Data Hub values.
- Role-fit estimates against known in-game role reports and actual position familiarity; weights are provisional coaching guidance.
- Steam/Game Pass-specific live process detection and separate module fingerprints.
- Complete staff, club, finances, contracts, injuries, registration and training feature layers.
- Actual live FM editing. The current read-only importer is not a safe basis for arbitrary writes; verified store/build-specific field mappings and compare-before-write/read-back/undo tests remain mandatory.

## Safety and source integrity

- No third-party GPL source implementation has been copied into this project.
- No new live memory write offsets have been introduced.
- The career save remains read-only through the save bridge.
- The local editor modifies only the Atlas SQLite copy and records an audit row per field update.
