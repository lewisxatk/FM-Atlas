# FM Atlas R3.7 — Unified Live Intelligence & CoachPro Scouting Release

## Purpose

R3.7 combines the planned R3.6 Live Intelligence & Fitness work and R3.7 Complete Scouting Workspace work into one coordinated release milestone. It is based on the R3.5.1 Aurora Frost application source carried forward in the R3.6 package.

This ZIP is a **unified source/validation package and implementation plan**, not a claim that every item below is already implemented or that a Windows executable has been built. The existing application features are retained; new capabilities must be implemented and tested on Windows before being marked complete.

## Workstream A — Live intelligence and data integrity

- Preserve the read-only FM27 process connector.
- Validate the exact FM27 module fingerprint before interpreting live structures.
- Preserve player UID identity and player → team → club linkage.
- Keep technical, mental, physical and goalkeeper attribute families separate.
- Retain CA/PA, reputation, positional suitability, contract and hidden-attribute evidence with provenance.
- Store candidate fitness observations as raw, unlabelled values until independently validated.
- Investigate condition and match sharpness on a 0–10,000 display scale only after their raw scale and offsets are confirmed.
- Investigate fatigue/jadedness separately; do not assume it shares the 0–10,000 scale.
- Keep full medical-record parsing out of scope for this release.
- Do not enable memory writes. Do not promote provisional fields into recruitment calculations.

## Workstream B — Complete scouting workspace

Planned implementation and acceptance criteria:

1. **Player search:** searchable player list, position/role filters, age, nationality, league/club, ability and attribute ranges.
2. **Three-column player workspace:** left filters, central results, right selected-player profile, following the Aurora Frost CoachPro layout.
3. **Player profiles:** separate goalkeeper/outfield views; attributes, positions, footedness, CA/PA, contract and confidence/provenance indicators.
4. **Club and staff databases:** searchable, linked to player records where identity evidence supports the relationship.
5. **Shortlists:** persistent named shortlists, add/remove, notes and CSV export.
6. **Player comparison:** side-by-side attributes, position suitability, age, ability and contract information; unknown values remain blank.
7. **Recruitment reports:** explain why a player matches filters; never fabricate scouting knowledge or use unverified fitness values.
8. **Database reliability:** schema migrations, stable IDs, duplicate handling, import logs, rollback-safe imports and refresh.
9. **CSV workflows:** documented templates, validation errors and clear import/export feedback.
10. **Responsive desktop UX:** consistent Aurora Frost styling, readable dense tables, keyboard-friendly search and sensible empty/loading/error states.

## Workstream C — Release quality

- Windows Release build must pass with zero errors.
- Existing R3.5.1 functions must pass regression checks.
- Validate database creation/migration and persistence across restarts.
- Validate import on a copy/test career before any wider use.
- Keep game process access limited to `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`.
- Publish both framework-dependent and self-contained win-x64 packages; verify the self-contained package on a clean Windows machine.
- Keep the previous known-good release as rollback.

## Fitness evidence rule

The Jayden Danns before/after comparison matched the same player UID. Raw observations changed at offsets `+0x258`, `+0x25A`, and `+0x25C`, while the in-game sharpness label changed from “Lacking Sharpness” to “Gaining Sharpness”. The follow-up also included a bruised-heel injury. This is correlation from one confounded observation, not proof of field semantics. See `docs-R3.6/R3.6-Fitness-Validation-Report.md`.

## Build on Windows

```powershell
dotnet restore .\FmAtlas.sln
dotnet build .\FmAtlas.sln -c Release
dotnet run --project .\src\FmAtlas\FmAtlas.csproj -c Release
```

Framework-dependent single-file publish:

```powershell
dotnet publish .\src\FmAtlas\FmAtlas.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o .\publish\win-x64
```

Self-contained publish (requires successful NuGet runtime package downloads):

```powershell
dotnet publish .\src\FmAtlas\FmAtlas.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o .\publish\win-x64-self-contained
```
