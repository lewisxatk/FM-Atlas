## 3. Static source findings

### Live memory writer — HIGH RISK / NOT ACCEPTED

Reviewed `LiveMemoryEditService.cs`, `Fm27BuildProfiles.cs` and `PlayerAttributeSchema.cs`.

Positive safeguards present in source:
- exact PE SizeOfImage + timestamp profile matching;
- unique player UID and name re-resolution;
- staged preview with expected original bytes;
- value-range checks and duplicate-field rejection;
- whole-batch preflight before first write;
- per-field session-generation check, read-back, guarded Undo and rollback attempts;
- hidden attributes and non-whitelisted structural fields rejected.

Important limitations:
- A PE fingerprint confirms a known module build, not the correctness of each player field offset or encoding.
- The visible attribute offsets are sourced from public reverse-engineering research and have not been witnessed against this user's running FM27 build.
- The save-load counter pointer/offset and player identity structure also require real-process validation.
- Partial-write rollback can be skipped if the game session changes; the code reports this, but this means rollback is not an absolute guarantee.
- No compile or runtime evidence exists for this writer.

**Decision:** do not enable or test live Apply/Undo yet. Keep the editor disabled. First build and test read-only import/identity on a disposable offline career; then independently verify each proposed field mapping before any write test.

### Data import/database

- Live import is kept separate from the existing scouting tables, which is a useful provenance boundary.
- Source documentation explicitly marks imported live candidate values provisional.
- Database schema and migration behaviour are large and require a real migration test against a COPY of `%LOCALAPPDATA%\\FmAtlas`; static inspection is not a substitute.
- Verify representative player, club, season, match, history and attribute counts after importing a copied save.

### Search and Value Finder

- Advanced Statistical Search constructs dynamic metric fields from imported facts and exposes multi-condition filters and per-90/minutes options.
- Value Finder labels its output as a relative screening index, not FM's hidden valuation formula.
- Both require dataset-based acceptance tests for missing values, duplicate field names, minutes thresholds, multi-condition logic and percentile population.

### Graphics

- Resolver reads the user's own `config.xml` mappings and constrains resolved paths to the selected graphics tree.
- It does not bundle facepacks/logos.
- Actual Game Pass graphics root, config variants, ID mapping and cache behaviour remain untested on the user's PC.
